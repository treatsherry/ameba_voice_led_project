# 第五階段：安全語音控制 LED

介面同時載入兩類繁體中文辨識文法：

- 指定控制語句：`左邊開燈`、`右邊開燈`，優先權與權重較高。
- 一般自由語句：用於顯示其他辨識文字。

只有結果來自指定控制語句文法、文字完全相符，且信心分數至少 0.20，才會轉換為 `BLUE_ON` 或 `GREEN_ON`。此門檻依本機引擎實測調整：合成的正確「左邊開燈」只有 0.25。即使自由語句辨識文字碰巧相同，也不會觸發。其他語句或信心不足時只留下紀錄，不傳送 LED 指令。

語音符合規則後仍須完成既有串列流程：電腦送出含識別碼的指令，收到相同識別碼的板子 `OK` 回覆後，介面才顯示板子回報狀態。逾時或通訊失敗時狀態顯示未知，不宣稱控制成功。

## 操作測試

每次先按「全部關燈」，再按「辨識一句」並說話：

1. 說「左邊開燈」，應顯示原文、送出 BLUE_ON，板子回覆 BLUE=1，目視藍燈亮。
2. 全部關燈後說「右邊開燈」，應送出 GREEN_ON，板子回覆 GREEN=1，目視綠燈亮。
3. 全部關燈後說「今天天氣很好」，可顯示辨識文字，但不得出現 BLUE_ON 或 GREEN_ON，兩燈保持關閉。
4. 拔除 USB 後說有效指令，介面應提示通訊失敗，燈號顯示未知。

辨識錄音仍只保存在本機 `build/speech-last.wav`，下一次辨識會覆寫。

## 自動語音測試結果

使用同一個 zh-TW 系統合成音源直接輸入辨識器：

- 「左邊開燈」→ BLUE_ON，通過。
- 「右邊開燈」→ GREEN_ON，通過。
- 「今天天氣很好」→ 不傳指令，通過。
- 「不要左邊開燈」「我想知道左邊開燈」「請不要右邊開燈」→ 均不傳指令，通過。

首次測試檔因 Windows PowerShell 5.1 將無 BOM 的 UTF-8 中文讀成亂碼而失敗；改為 UTF-8 BOM 後才得到有效測試結果。真人語音與實體 LED 仍需下一步驗證。

## 真人與實體 LED 驗證

使用者已在新版介面完成以下測試並回報全部通過：

- 說「左邊開燈」：介面送出 BLUE_ON、板子回覆藍燈狀態、實體藍燈亮。
- 說「右邊開燈」：介面送出 GREEN_ON、板子回覆綠燈狀態、實體綠燈亮。
- 說「今天天氣很好」：視為非控制語句，沒有傳送 LED 控制指令，燈號保持不變。

第五階段功能串接通過。這是功能測試各一次，尚未取代正式驗收要求的兩句各五次及一次通訊中斷紀錄。
