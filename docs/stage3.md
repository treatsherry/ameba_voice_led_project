# 第三階段：Windows 操作介面

## 啟動

雙擊專案根目錄的 `Start-LedControl.cmd`，即可開啟「Ameba Mini LED 控制台」。
環境：Windows、Windows PowerShell 5.1、系統內建 Windows Forms；不需另裝 Python 或第三方套件。
板子繼續使用第二階段 `led_control/led_control.ino`，不需重新燒錄。

## 使用方式

1. 插入 USB，選擇對應連接埠（目前 COM4），按「查詢狀態」。
2. 按「左邊開燈（藍燈）」或「右邊開燈（綠燈）」；兩顆燈獨立控制。
3. 「全部關燈」可重設下次測試的燈號。
4. 「測試無效指令」送出 INVALID，板子應拒絕且不改變燈號。
5. 「匯出操作紀錄」儲存畫面中的 TX、RX 與錯誤訊息為文字檔。

語音辨識欄目前明確標示尚未啟用，下一階段才加入語音。
介面顯示最近一次手動操作的指令與實際回覆，背景查詢不覆蓋這兩欄。
LED 狀態顯示板子最後回報的輸出狀態與時間，無法偵測 LED 硬體是否真的發光。

## 連線與錯誤

- 預設每 3 秒送 STATUS 確認；可取消勾選。取消後須手動查詢，最後回報並非持續監測。
- 每次通訊最多等待回覆 3 秒，期間停用指令按鈕，避免同時占用串列埠。
- 通訊在背景執行，視窗仍可移動與操作。
- 拔線、埠被占用或回覆逾時時，LED 狀態顯示「未知」，不以送出的命令推算成功。
- USB 重接後若仍為相同埠號，可由背景查詢恢復；埠號改變時重新掃描並選擇。
- 關閉視窗不改變 LED；如果拔線同時切斷供電，重新供電時韌體初始化為全暗。
- 操作紀錄保留近期約 60,000 字元，超過後清空；重要紀錄請及時匯出。

## 已執行驗證

透過 `powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\ui\Led-Control.ps1 -SmokeTest`，
在實際 Windows Forms 事件迴圈與背景通訊工作中驗證：

- COM4 的 STATUS 回覆能更新視窗欄位。
- INVALID 顯示 ERR_COMMAND，兩燈回報狀態不變。
- COM9999 開埠失敗時，顯示未知、未送出。
- 改回 COM4 可成功查詢並恢復。

上述自動測試不改變燈號。

使用者已在可見視窗依序測試「左邊開燈」「全部關燈」「右邊開燈」及「測試無效指令」，
確認「視窗正常，燈號與回覆都正確」：實體燈號與畫面回報一致，無效指令被拒絕且綠燈保持亮著。
第三階段操作介面驗收通過；語音辨識尚未加入。
