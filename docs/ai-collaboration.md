# AI 協作紀錄

## 第一階段：硬體確認

關鍵提示：「先確認是否連接且能控制 AMB82-mini」，接著授權建立與上傳 LED 測試。

AI 產出 `led_test/led_test.ino`，以藍燈、全暗、綠燈、全暗循環驗證腳位與控制邏輯。
Windows 偵測 COM4，燒錄後使用者目視確認，電腦也收到循環訊息。

實際問題與修正：

1. 編譯因 `locale::facet::_S_create_c_locale name not valid` 失敗。將該程序語系設為 `LC_ALL=C`、`LANG=C` 後成功。
2. Arduino CLI 獨立 upload 找不到有效產物。檢查套件 `platform.txt`，確認編譯檔與工具目錄韌體 SHA-256 一致，再使用官方 `image_windows.exe` 成功燒錄。
3. 燒錄後沒有程式輸出。使用者按 RESET 後，燈號與串列輸出均正常。

## 第二階段：指令通訊

關鍵提示：提供正式專題規格，並回覆「好，下一步」，依約開始電腦指令控制與板子回覆。

AI 產出：

- `led_control/led_control.ino`：只接受固定指令，回報兩燈輸出狀態。
- `tools/Send-LedCommand.ps1`：傳送指令、配對識別碼與回覆，通訊失敗不偽造狀態。
- `tools/Test-LedControl.ps1`：比對有效、重複、無效指令與狀態查詢的實機回覆。

驗證原則：編譯成功只證明可建置，還必須完成燒錄、串列回覆比對及目視燈號驗證。
不以電腦送出的內容直接當作實際執行成功。測試進度見 `stage2.md`。

已完成測試：8 項實機回覆比對通過，額外的格式錯誤、過長與含 NUL 封包均被拒絕。
使用者分別確認「只有藍燈亮」與「只有綠燈亮」，與板子回覆一致。
使用者實際拔除 USB 後查詢，工具回報通訊失敗，LED 狀態留空，未誤報控制成功。

## 第三階段：操作介面

關鍵提示：「那可以開始下一步了」，依先前約定建立操作介面，再於下一階段加入語音。

AI 產出 `ui/Led-Control.ps1` 與 `Start-LedControl.cmd`，沿用已驗證的傳輸工具。
Windows Forms 顯示按鈕、板子最後回報狀態、傳送指令、原始回覆與可匯出的操作紀錄。
背景工作執行串列通訊，避免斷線等候期間卡住視窗；以定時 STATUS 查詢偵測失聯。

驗證：重新插入 USB 後查詢正常；在實際視窗事件迴圈中驗證板子回覆、無效指令、錯誤埠號與恢復。
為相容 Windows PowerShell 5.1，含中文的介面腳本使用 UTF-8 BOM，避免中文以系統預設編碼讀取後亂碼。

使用者實際操作視窗的開燈、全部關燈及無效指令按鈕後，回覆「視窗正常，燈號與回覆都正確」。
第三階段完成介面、板子回覆與實體燈號的人工驗證。

## 第四階段：先驗證語音辨識

關鍵提示：「下一步」，依前一階段約定先顯示麥克風辨識文字，驗證後再連動 LED。

AI 先檢查已安裝引擎，發現 zh-TW 本機引擎可用。沙箱內雖可列舉引擎卻無法初始化；在允許的沙箱外環境重試後，引擎及麥克風均可初始化。
新增 `ui/SpeechCapture.cs`、麥克風與取消按鈕、`tools/Test-SpeechCapture.ps1`。
靜音 WAV 與取消收音測試通過，原有 UI 通訊整合測試也通過。真人辨識效果待回報。

真人測試問題：使用者回報系統麥克風測試正常，程式卻顯示 15 秒超時、峰值 100/100。
依紀錄可確認有收音，不能判定是裝置無輸入，也不能僅以峰值判定爆音。
AI 修改為 8 秒先呼叫 RecognizeAsyncStop 嘗試完成辨識，18 秒才取消，並加入即時音量、SpeechDetected 與 AudioSignalProblem 診斷；待真人重測。
停止收音測試另外發現 SAPI 對 graceful stop 也可能回報 Cancelled；因此獨立記錄使用者取消意圖，保留引擎已接受的 SpeechRecognized 結果，不使用被拒絕的猜測文字。修正後靜音、取消、停止收音與 UI 整合測試通過；真人辨識是否改善仍待確認。

使用者確認 Windows 錄音回放清楚，但程式仍產生錯字。AI 新增辨識片段的本機 WAV 保存與播放功能，用來對照程式實際取得的聲音。
以 zh-TW 系統合成「左邊開燈」直接輸入辨識引擎、不經麥克風，仍得到「所編排等」；因此目前引擎本身對目標句的辨識效果也是問題來源。錄音保存、載入、停止、取消與 UI 通訊回歸測試皆已通過。

使用者回放 `speech-last.wav`，確認程式取得的真人語音清楚完整，因此停止調整麥克風，改用「指定控制文法＋一般語句文法」。
首次合成語音測試因 PowerShell 5.1 把無 BOM 的 UTF-8 中文讀成亂碼而失敗；轉為 UTF-8 BOM 後，限定文法能正確辨識目標句，但正確句信心分數只有 0.25。將門檻由 0.65 調為 0.20，同時要求控制文法來源與文字完全相符。
最後以兩句有效指令、一般語句，以及三句包含目標關鍵字的否定／詢問語句測試；有效句分別映射 BLUE_ON、GREEN_ON，其餘四句均未產生控制指令。

真人實機測試結果：使用者依序測試「左邊開燈」「右邊開燈」「今天天氣很好」，回報全部通過。兩句控制語句完成語音辨識、指令傳輸、板子回覆與實體 LED 驗證；非控制語句沒有改變 LED。
